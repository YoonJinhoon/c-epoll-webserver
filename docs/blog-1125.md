# 웹 서버 5일차: timeout (11/25)

## 1. epoll_wait가 깨어나는 걸 눈으로 보기
`epoll_wait(..., -1)` → `1000`으로 바꾸고, 바로 다음 줄에 `printf("[main] 깼음 n=%d\n", n);`

```
[main] 깼음 n=0                              ← 1초 동안 아무 일 없음
[main] 깼음 n=1                              ← ① 새 연결 (할 일 A)
[fd 5] 연결됨 -> 보관함 만들고 등록
[main] 깼음 n=1                              ← ② 요청 데이터 (할 일 B)
[fd 5] 조각 77 바이트 도착 -> 보관함 77 바이트
...
[main] 깼음 n=0                              ← 다시 1초마다
```

### 내 4줄 채점
1. **"n은 fd 목록에 저장된 fd의 개수?"** ❌ → **이번에 할 일이 생긴 fd의 개수.** 근거: curl이 오기 전 목록에는 listen fd 1개가 있었는데 `n=0`. ②에서는 목록에 2개(listen, fd 5)가 있었는데 `n=1`
2. **"둘 다 바로 아래 줄의 로그가 근거"** ✅
3. **"①: 커널로부터 fd 5를 받은 연결"** ✅ 할 일 A. 단, ①에서 epoll이 알려준 fd는 fd 5가 아니라 **listen fd**("새 연결 왔음"). fd 5는 깨어난 **다음에** `accept`가 받아온 번호 ← 내가 놓친 섬세한 부분
4. **"②: 해당 연결이 요청 데이터를 보냄"** ✅ 할 일 B. 이때 epoll이 알려준 fd가 fd 5

### -1과 1000
- `-1` = "영원히"가 아니라 **할 일이 생길 때까지 무한정**. 어제 1,019개가 가만히 있어서 영원히 안 깨어난 것처럼 보였다
- `1000` = "1초 잔다"가 아니라 **최대 1초**. 그 사이에 curl이 오면 바로 깬다
- `events`가 복수형인 이유: 한 번 깰 때 할 일이 n개일 수 있다 (배열 최대 64칸)

### 함정: make 했는데 printf가 안 찍힘
`make`할 때 `printf` 줄이 아직 저장 안 된 상태였다 → 옛날 코드로 컴파일. 11/23의 "옛날 ./webserver를 검사함"과 같은 종류. **실행 파일이 내가 보는 코드와 같은가?**

## 2. timeout: 1초마다 모든 보관함 훑기
- 보관함에 `last_active` = 마지막으로 무언가 도착한 시각. 갱신은 두 번: **연결된 순간**(`conn_open`) + **바이트가 도착할 때마다**(`conn_on_data`, 머리든 본문이든)
- main 루프에서 `epoll_wait` 처리 **다음에** `conns[0]`~`conns[1023]`을 하나씩 본다. 빈 칸은 건너뛰고, 연결이 있으면 오래 조용했는지 검사
- `epoll_wait`가 최대 1초마다 깨니까, 그 다음 줄의 훑기도 **1초마다** 실행된다 (`깼음 n=0`이 1초마다 찍힌 것과 같은 원리)

### 내가 쓴 조건 (두 번 만에)
- 1차: `IDLE_TIMEOUT >= now - c->last_active` → 반대 (방금 연결된 것: 5 >= 0 참 → 바로 닫힘, 6초 조용한 것: 5 >= 6 거짓 → 안 닫힘)
- 2차: `IDLE_TIMEOUT <= now - c->last_active` → 5초 이상 조용하면 닫는다

### 연결 칸이 1,019자리인 이유 (표로)
`conns` 표는 칸 1,024개, **칸 번호 = fd 번호**. 앞 다섯 칸은 서버가 이미 쓴다.

| fd 번호 | 누가 쓰나 | 클라이언트가 받을 수 있나 |
|---|---|---|
| 0 | 표준 입력 (모든 프로세스) | ❌ |
| 1 | 표준 출력 (모든 프로세스) | ❌ |
| 2 | 표준 에러 (모든 프로세스) | ❌ |
| 3 | listen 소켓 (우리 서버가 첫 번째로 엶) | ❌ |
| 4 | epoll 목록 (우리 서버가 두 번째로 엶) | ❌ |
| **5 ~ 1023** | **클라이언트 연결** | ✅ **1,019개** (1023 − 5 + 1) |
| 1024 이상 | `conn_open`이 `fd >= MAX_FDS`라서 바로 close | ❌ |

어제(11/24) 로그의 `연결됨` 1019가 이 계산과 정확히 맞았다.

### timeout 줄 수 예측 (1019) — 클라이언트별로 따라가기
`grep -c timeout` = `timeout` 글자가 든 줄 수. 그 줄은 훑기 안 `printf` 한 곳에서만 찍힌다. 훑기는 `conns` 표에 **보관함이 있는 칸만** 검사 → "표에 들어간 적 있고 + 5초 조용했던 연결"만 찍힌다.

| 누가 | 몇 개 | 무슨 일이 생기나 | 찍히는 로그 | `timeout` 줄 |
|---|---|---|---|---|
| 먼저 온 nc | 1,019 | fd 5~1023을 받아 표에 들어감 → 아무것도 안 보냄 → 5초 뒤 훑기에 걸림 | `연결됨` → `timeout` | 1,019 |
| 나중에 온 nc | 81 | fd 1024 → `conn_open`에서 표에 안 넣고 바로 close | `꽉 참` | 0 |
| 붙인 직후 curl | 1 | 자리가 없어서 바로 close | `꽉 참` | 0 |
| 10초 뒤 curl | 1 | 빈자리 받음 → 요청 → 200 → 닫음 (5초 전에 끝남) | `연결됨` → `200` → `close` | 0 |
| 합계 | | | | **1,019** |

## 4. S6 timeout 정리 (내 3줄 + 바로잡은 것)
1. **본 것:** 느린 클라이언트 1,100개를 붙이자 (그중 자리를 받은 건 1,019개), 붙인 직후 curl은 실패, 40초 뒤 curl은 성공. timeout으로 닫힌 연결은 1,019개
   - 바로잡음: 처음엔 "1019개를 붙이자"라고 씀 → 붙인 건 1,100, 자리 받은 게 1,019
2. **방법:** `epoll_wait`의 마지막 인자를 `-1` → `1000`(ms)으로 바꾸면 할 일이 없어도 최대 1초마다 깨어난다. 깨어난 다음 줄에서 모든 보관함을 훑으며 `지금 시각 − last_active`가 30초 이상이면 닫는다
   - `last_active` = **마지막 요청 데이터 조각이 서버에 도착한 시각** (클라이언트가 보낸 시각 ❌ — 서버는 도착만 안다). 그리고 **연결된 순간**에도 기록한다

막으려면: "**연결된 순간부터 요청 전체를 30초 안에**" (전체 마감) 같은 규칙. 단, 이것도 느린 네트워크에서 큰 파일을 정직하게 올리는 사용자를 자른다 → 실제 서버는 둘을 같이 쓰거나 "초당 최소 몇 바이트" 규칙을 쓴다.

왜 처음부터 전체 마감으로 안 했나: S4에서 찾은 문제가 "아무것도 안 보내고 영원히 붙어 있음"이었고, 그걸 막는 가장 단순한 방법(필드 하나)이 idle timeout이었다. 조금씩 보내는 공격은 그다음에 알게 됐다.

### 점심 뒤에 읽을 것: 왜 "모든 보관함"을 훑나
- epoll이 알려주는 것: 할 일이 **생긴** fd (`events`, n개)
- timeout이 알아야 하는 것: 30초 동안 할 일이 **없었던** fd
- 조용한 연결은 할 일이 없으니 **`events`에 절대 안 나온다** → epoll은 "누가 조용한지" 모른다 → 서버가 직접 `conns[0]`~`conns[1023]`을 한 칸씩 열어 시각을 확인
- 질문: timeout 검사를 `for (i < n)` 안에서(= `events`에 나온 fd만) 하면 어떻게 되나?

### (점심 뒤) 훑기 이해 ✅
- 30초 실험 때 화면이 `[main] 깼음 n=0`으로 꽉 찼다 → 느린 클라이언트 1,019개가 붙어 있는데도 **n=0 = events가 비어 있음**
- main 루프 안 반복문은 두 개: ① `for (i < n)` events 처리 → n=0이면 **0번** (`0 < 0` 거짓) / ② `for (fd < 1024)` 훑기 → 항상 1,024번
- 처음엔 ①이 몇 번 도냐는 질문에 "1024번" → 반복문 둘을 헷갈림
- 내 답: timeout 검사를 ① 안에 넣으면 **안 닫힌다. events에 한 번도 안 나오니까** ✅
