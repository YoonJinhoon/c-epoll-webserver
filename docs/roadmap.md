## 원칙
- `experiments/` = 버리는 실험 코드 (개념을 눈으로 보기). `src/` = 진짜 서버 (제출물)
- 단계마다 **끝 조건**을 먼저 정하고, 끝 조건은 **명령 한 줄로 확인할 수 있게** 만든다 (`tests/`)
- 동시성 방식: **epoll** 기반. 마지막에 하이브리드(epoll + 코어 수만큼 스레드)

## src/ 단계 (진짜 서버)
순서 기준: 앞 단계가 뒤 단계의 바탕이 되는 순서. 🔴 피해 큰 것은 그 단계 안에서 먼저.

| 단계 | 할 일 | 관련 요구사항 | 끝 조건 (예정) | 상태 |
|---|---|---|---|---|
| S1 | epoll 뼈대 + **요청을 끝까지 읽기** (빈 줄 `\r\n\r\n`이 올 때까지, 조각나서 와도) | 연결-1·3·4, HTTP-2 | 요청을 두 번에 나눠 보내도 응답이 한 번만 옴 / 느린 클라이언트 테스트 PASS | ⬜ 다음 |
| S2 | 요청 라인·헤더 파싱 + 응답 만들기 | HTTP-1·3·5 | 파서 단위 테스트, `curl -i` 결과가 검증된 서버와 같음 | ⬜ |
| S3 | 정적 파일 + MIME + 404/403 + 루트 밖 접근 막기 | 파일-1~4 | `curl`로 html/png 받기, 없는 파일 404, `/../` 차단 | ⬜ |
| S4 | POST 본문 (Content-Length) + 동적 처리 | HTTP-4, 파일-5 | 본문 크기만큼 정확히 읽음, CGI 또는 백엔드 응답 | ⬜ |
| S5 | Reverse Proxy: 경로 라우팅 + Round-Robin + 백엔드 타임아웃 | 프록시-1~4 | 백엔드 2개에 번갈아 전달, 죽은 백엔드에 502/504 | ⬜ |
| S6 | 자원·종료: 끊김 처리, SIGPIPE, SIGINT/SIGTERM, 이상한 요청 | 자원-1~5 | ASan 에러 0, 클라이언트가 중간에 끊어도 서버 생존 | ⬜ |
| S7 | ④ 하이브리드 (epoll + 코어 수만큼 스레드) + keep-alive | 연결-6, HTTP-6 | 부하 테스트에서 스레드 1개 대비 처리량 비교 | ⬜ |
| S8 | 마무리: Makefile, CLI 인자, 단위·기능·부하·메모리 테스트 정리, README | 제출-1~6 | `make test` 한 번에 전부 통과 | ⬜ |

책: CSAPP 11장 (제출-7) — 단계 사이사이에.
