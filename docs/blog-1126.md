# 11/26(목) 웹 서버

## 1. 아침: S5-d 로그에 질문 5개 (모범 답)

로그 (nc가 대답 안 하는 상태, D가 `/index.html` 요청):
```
[fd 5] 연결됨 -> 보관함 만들고 등록
[fd 5] 조각 86 바이트 도착 -> 보관함 86 바이트
[fd 5] 머리 끝 발견 (머리 86 바이트)
[fd 5] 파싱 성공: method=GET path=/api/hello
[fd 5] 백엔드 8001 에 연결 (백엔드 쪽 fd 6) -> 요청 86 바이트 전달
```
D: `curl: (28) Operation timed out after 5002 milliseconds with 0 bytes received`

| # | 질문 | 모범 답 | 내가 빠뜨린 것 |
|---|---|---|---|
| ① | 있는 줄 | curl 접속 → `accept`로 fd 5 → `conn_open`이 보관함 만들고 **epoll 감시 목록**에 등록 → 요청 86바이트가 **커널 안 fd 5 소켓**에 도착 → `epoll_wait`가 깨움 → `read`로 보관함에 복사 → 보관함에서 `\r\n\r\n` 찾음 → 요청 라인을 **공백으로 잘라** method/path/version → `/api/`로 시작 → **우리 서버가** `socket`으로 fd 6을 받아 8001에 `connect` → 86바이트를 fd 6에 씀 | 등록 위치, 도착 위치 / "key=value 파싱" → 공백 3조각 / "백엔드가 fd 6을 받음" → 주어는 **우리 서버** |
| ② | 없는 줄 | (a) `백엔드 응답 N 바이트를 그대로 전달` 없음 → fd 5 처리가 안 끝남 (b) D의 `[fd 7] 연결됨` 없음 → D는 accept조차 안 됨 | "fd 6에 보관함이 없음"은 원래 정상 (conn_open을 안 거침) |
| ③ | 숫자 | 86 → 86: curl이 보낸 그대로 백엔드에 전달 (손대지 않음) / fd 6: 5 다음 가장 작은 빈 번호 → 그 사이 다른 accept 없음 | 같은 86의 의미, fd 6이 6인 이유 |
| ④ | 멈춘 곳 | 마지막 줄 다음 = `proxy_to_backend`의 `while (read(fd 6) > 0)` → **main 스레드가** 백엔드의 응답 또는 닫힘을 기다리며 블로킹 | 주어(main 스레드), 기다리는 대상에 "닫힘" |
| ⑤ | 빠진 재료 | (1) 스레드는 **1개** (2) `read`는 데이터나 닫힘이 올 때까지 블로킹 (3) fd 6은 epoll에 등록 안 됨 → 그래서 `epoll_wait`로 못 돌아감 → D를 accept 못 함 | "누가 언제 read하나" = main 스레드가, 요청을 보낸 직후 |

**3단계 사슬:** `read(fd 6)` 블로킹 → 그래서 `epoll_wait`로 못 돌아감 → 그래서 D를 accept 못 함
